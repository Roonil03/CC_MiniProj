2. DESIGN COMPLIANCE (schemas stuck to, nothing invented)
--------------------------------------------------------------------------------
- Node/workload JSON: Design Sec 16 field names kept verbatim
  (node_id, cpu_total/used, memory_total_mb/used_mb, network_in/out_mbps,
  latency_to_cloud_ms, health, timestamp; workload service_id, replicas,
  cpu/memory request+usage, request_rate, p95_latency_ms, slo_ms).
- NATS events: Sec 53 NODE_METRIC_UPDATED and Sec 54 RESOURCE_DECISION shapes.
- Sync cadence Sec 17: CPU/mem/net 1s (not 100ms); pod/health slower by design.
- Fidelity formula + autonomy bands Sec 18 implemented exactly
  (>0.95 autonomous, 0.90-0.95 restricted, 0.80-0.90 simulation-only,
  <0.80 disabled; stale always disables).
- Safety gates Sec 33-36 + fallback Sec 64: fail-closed on stale DT, low
  prediction confidence (<0.80), SLO prob (>0.10), unhealthy nodes, no
  destination capacity, storm (>3 migrations/min), cooldown (30s/node).
- Migration duration estimate Sec 31: T = S_state/B_effective + T_overhead.
- Boundary Sec 66 preserved: ONLY the Go controller touches the K8s API
  (least-privilege Role); Python/RL proposes candidate actions via NATS/HTTP.
- Ports match .env.example: twin 8080, controller 8081, telemetry 8082.
- Framework choice: Gin (approved); local K8s target: k3d; twin store
  Phase-1: in-memory hot store + Redis write-through path, Postgres/Timescale
  DDL provided for the durable sink (Redis-then-Postgres decision honored).
