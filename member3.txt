Ownership and boundary

  Node, Digital Twin, RL, safety, or Kubernetes services.
- Python records telemetry and serves forecasts. It does not issue resource
  decisions or control Kubernetes. Integration and merging are for the other
  members later.

Deliverables against Design.md sections 72-73
1. Dataset schema: implemented and validated for the existing Go
   NODE_METRIC_UPDATED event: timestamp, node ID, CPU/memory fractions, and
   incoming/outgoing network Mbit/s. The wider design's application latency,
   queue, request rate, placement, migration, and SLO fields have no verified
   producer in this checkout and are not fabricated.
2. Ingestion: JSONL import/replay, durable JetStream consumer, commit-before-ack
   SQLite recording, duplicate/conflict handling, export with content hash and
   missing-bucket report. Live NATS collection still needs a running stack.
3. Baselines: persistence, ARIMA, and ETS implemented and smoke-tested.
4. Recurrent models: LSTM and GRU training/evaluation implemented and tested.
5. Lightweight models: compact temporal convolution and a one-layer Transformer
   encoder (2,418 parameters) implemented, trained, saved, reloaded, and
   evaluated on a labeled synthetic software fixture. Real workload comparison
   remains pending.
6. Prediction service: versioned model registry, explicit activation, artifact
   hash verification, read-only /models and /predictions, freshness and token
   checks, Dockerfile, and service guide. The Transformer was served through a
   real local Uvicorn HTTP socket. The Docker image was not built because the
   Docker daemon is unavailable here.
7. Operational benchmark: direct inference, in-process HTTP, and optional
   live-network HTTP measurement with selected-model verification, latency
   summary, client CPU/RSS, model size, host, and dataset identity. The actual
   target-hardware/testbed benchmark is pending a real recorded dataset and
   deployment.

Verification on this checkout
- All 15 Member 3 unit/smoke tests pass, including the Transformer shape,
  training/artifact reload, registry activation, and existing data/API checks.
- Python compilation, pip dependency check, and Git whitespace/diff checks
  pass. No datasets, weights, credentials, or virtual environments are tracked.
- Local live HTTP smoke: 360 synthetic 1-second node samples, Transformer CPU
  forecast with 8-step history and 1/2-second horizons, 2 training epochs,
  Uvicorn on localhost, and 50 measured HTTP requests. Direct inference p95
  was 0.61 ms; localhost HTTP p95 was 11.53 ms on this Windows host (12 logical

  This verifies software execution only: synthetic data, an extended freshness
  limit, and local hardware do not establish real forecasting accuracy or the
  design's production <100 ms prediction target.

Real-data evaluation completed 2026-11-01
- Compared persistence, ARIMA, ETS, LSTM, GRU, temporal convolution, and
  Transformer on the checksummed 5,004-sample k3d CPU trace with chronological
  partitions and 5/10/30/60-second horizons. The 60-sample history had no valid
  windows because of capture gaps; a declared 20-sample history was used without
  imputation. Results, metadata, plots, and limitations are versioned under
  experiments/analysis/k3d-20261101-forecasting.
- Temporal convolution was selected on validation RMSE and met the local-host
  latency budget, but low interval coverage and idle/shared-host data mean no
  model is approved for activation. Synthetic smoke results remain software
  checks only.
